出勤資料頁面 改良提案

功能位置：企業管理專區 > 員工資料設定 > 出勤資料（E080）

出勤資料頁是每月出勤登打、線上單據匯入、打卡紀錄檢查的核心作業頁面。 本次以不動正式系統的方式，先做出可以實際點擊操作的改良原型， 將原本擠在同一畫面的十多顆按鈕，重新整理成清楚的作業動線。

▶ 開啟互動原型（可實際點擊操作） 原型為靜態展示頁，使用假資料，不會影響正式系統。內建「切換舊版佈局」按鈕，可一鍵切回現行版面現場對照。
🗂️

作業分流，不再誤點

十多顆同色按鈕改為三個作業頁籤，一次只看到當下任務需要的功能。

🛡️

防呆保護整月資料

「清除所有員工紀錄」需輸入月份才能執行，杜絕一鍵誤刪整月出勤。

⚡

編輯順暢不刷頁

逐格修改改為彈出視窗編輯，欄位有標題、有空間，畫面不再整頁重新整理。

🖥️

大小螢幕都好用

版面改為自動適應，小筆電到大螢幕都完整呈現，不再被裁切出現雙層捲軸。

01 WHY

現況痛點

現行頁面功能齊全，但十多年累積下來，操作介面已出現以下問題：

按鈕牆：十多顆同色按鈕擠在左欄

匯入、下載範本、清除單人、清除全部……全部長得一模一樣、沒有分組，新手要靠記憶找按鈕，日常動作與危險動作混在一起。

誤刪風險：清除整月資料只有一個確認框

「清除所有員工紀錄」按下去只跳一個「確定/取消」，手滑點過就會刪掉全公司整月出勤資料。

重要規則藏在滑鼠提示裡

「自動轉入的加班單與補休單不會被刪除」這類關鍵規則，只有滑鼠停在按鈕上才看得到，實務上幾乎沒人發現。

逐格編輯體驗差，整頁不斷刷新

在表格內直接編輯，一列九個欄位擠在窄欄裡；改一個下拉選單整頁就重新整理一次，還得自動捲動找回剛剛編輯的位置。

版面尺寸寫死，小螢幕被裁切

各區塊高度、寬度都是固定像素，筆電或投影解析度較低時內容被切掉，出現「捲軸裡還有捲軸」。

跨月匯入是事後才攔截

匯入區間與出勤月份不一致時，要等按下按鈕才跳警告；使用者常在警告出現後才發現填錯。

改良前正式系統實際畫面

所有功能攤平在同一畫面：左欄十多顆同色按鈕無分組、無主次，「清除所有員工」混在日常按鈕之中；固定高度的綠框、紅框面板讓內容被裁切。

改良後互動原型畫面

條件在上、名單在左、作業分三個頁籤；危險動作獨立為紅色選單，打卡異常數量直接顯示在頁籤上，補休剩餘時數綠底大字呈現。

改良前表格內逐格編輯

按下「編輯」後整列變成擠在窄欄裡的輸入框與下拉選單，右側欄位被推出畫面；改一個下拉整頁就重新整理一次。

改良後彈窗編輯

欄位有標題、分區與呼吸空間；由加班單自動轉入的資料會明確提示「僅能修改時數」，不再靠猜。

改良前自製浮動面板

「新增」開啟的是絕對定位的自製面板：無遮罩、無框線階層、蓋在表格上，位置寫死在畫面 45% 處。

改良後標準彈窗＋防呆

標準 Bootstrap 彈窗有遮罩與焦點管理；高風險的「清除所有員工」需輸入月份字串才能按下確認，並先揭示影響人數與筆數。

點任一張圖可開啟全螢幕新舊並排對照。「改良前」為正式系統（測試環境資料）實際畫面；「改良後」為互動原型畫面。原型內建「切換舊版佈局」按鈕，簡報時可現場一鍵對照。

02 WHAT

新版架構總覽

畫面依「先選條件 → 再選人 → 再作業」的順序重新分層：

① 出勤月份列（全頁統一條件）

  • 年、月選擇器移到頁面最上方，成為整頁唯一的全域條件。
  • 匯入、檢查等區間預設自動同步此月份，從源頭避免跨月誤匯。

② 員工清單卡片化

  • 原本十欄表格（其中七欄被隱藏）改為卡片：姓名粗體＋「編號 · 部門 · 計薪方式」副標。
  • 部門下拉＋單一關鍵字框（姓名/編號合併），少填一格、少一次判斷。
  • 選中員工以藍色側條標示，且姓名同步顯示在工具列、彈窗標題與清除確認中——隨時知道「現在在操作誰」。

③ 三個作業頁籤

  • 出勤明細與統計：日常登打、修改與當月統計、加班換補休資訊。
  • 匯入 / 匯出：線上申請/打卡匯入、Excel 匯入、範本與資料下載集中管理。
  • 打卡紀錄檢查：檢查條件、結果表格化、可匯出；異常筆數以紅色數字顯示在頁籤上，主動提醒。

④ 放大 / 還原模式

  • 一鍵隱藏月份列與員工清單，明細表拉到近乎全螢幕。
  • 月底大量核對明細時不必調整瀏覽器縮放。

04 HOW

技術說明

原型刻意零新依賴，全部沿用系統既有技術棧，將導入成本降到最低：

零新框架，沿用既有資產

  • Bootstrap 3.3.7、AdminLTE 2、jQuery 2.2.3、bootstrap-datepicker 全部取自現行專案。
  • 沿用 E01_Style.css 與 E01.Master 的 header / 側選單結構，視覺與現行系統完全一致。
  • 不需引入任何新套件、不需升級前端框架。

彈窗標準化

  • 原本 4 個 display:none 絕對定位的假彈窗 Panel ＋ 6 個自訂顯示/隱藏函式，全面改為標準 Bootstrap modal。
  • 自動獲得遮罩、ESC 關閉、焦點管理；寫死 1280px 的寬度改為百分比＋上限。

版面與樣式現代化

  • 固定像素高度（460/500/600/700px）＋ float 排版，改為 CSS Grid ＋ 視窗比例高度，設三個響應斷點。
  • 表頭 sticky 固定、數字欄右對齊等表格細節統一處理。
  • 4 段各自宣告的 datepicker 初始化收斂為一行統一設定。

減少 PostBack 與隱藏欄位

  • 編輯移入 modal 後，可移除表格內含 AutoPostBack 的下拉與捲動補救程式。
  • 員工清單原以 CSS 隱藏 7 個欄位仍全量輸出，改版後僅呈現必要資訊。
  • 年份下拉 23 個寫死項目，正式導入時改為動態產生。
05 NEXT

後續導入規劃

目前完成的是可操作的靜態原型，尚未修改正式系統。建議依下列階段導入：

1

規格確認（本次報告）

以本原型為畫面與行為規格，收斂資訊部門、顧問師與管理層的意見，定版後不再重新發散。

2

正式頁面版面移植

將原型的頁籤結構、工具列、員工清單移植到正式 E080 頁面，先做到「長得一樣」，後端邏輯不動。

3

後端接線與行為改造

逐格編輯改為彈窗編輯、清除防呆（輸入月份確認）、跨月檢核前移、檢查結果表格化。此階段工作量最大，可再細分批次上線。

4

測試、驗收與上線

以實際月結流程演練（登打 → 匯入 → 檢查 → 清除重匯），由人資實際操作驗收後切換上線。

⚠ 風險與注意事項
  • 明細表格由「表格內編輯」改為「彈窗編輯」是工作量最大的一段，建議獨立估時並優先處理。
  • 現行頁面多處依賴整頁 PostBack 與自訂彈窗函式，改造時需逐一確認既有行為（含匯入確認流程）不被破壞。
  • 原型使用假資料，欄位內容與權限控制需在移植時對回正式資料來源與既有權限機制。
